# TRD — 현장별 공정·기성 대시보드

## 한눈에 보기

- **도구:** Next.js + TypeScript 한 프로젝트로 화면 4개와 AI 요청 창구 1개를 만듭니다. 자동 검사는 Vitest입니다.
- **자료와 계산:** 파일 읽기·검사·계산·CSV 만들기는 모두 브라우저에서 합니다. 서버 저장과 데이터베이스는 없습니다.
- **AI:** Gemini API(`gemini-3.8-flash`)를 서버에서만 부릅니다. API 키는 서버의 `.env.local`에만 두고 브라우저로 보내지 않습니다.
- **비용:** 월 0원(무료 구간). GitHub 저장과 Vercel 배포는 사용자가 별도로 요청한 뒤에만 진행합니다.
- **계산 검증:** 같은 계산 코드를 화면과 AI 요청이 함께 쓰고, `data/검산표.md` 숫자로 자동 검사합니다.

> 자료는 교육용 가상 자료입니다. `(AI 결정)`은 실습조건·PRD·FRD에 없어 AI가 정한 부분입니다. 앞 문서에서 정한 기능은 바꾸지 않았습니다.

## 1. 사용하는 기술과 고른 이유

| 구분 | 사용하는 것 | 고른 이유 |
|---|---|---|
| 만드는 도구 | Next.js(화면과 서버를 한 프로젝트로 만드는 도구) + TypeScript | 실습조건에 정해져 있습니다. 화면 4개와 AI 요청 창구 1개를 한 프로젝트에서 만듭니다. |
| 화면 구성 | React 화면 + Next.js 페이지 이동(App Router) | 페이지를 옮겨도 가져온 자료와 필터 선택을 유지해야 합니다(FRD F3). 이동은 페이지를 새로 불러오지 않아 자료가 남습니다. |
| 화면 꾸미기 | Tailwind CSS(미리 만든 작은 스타일 조각을 조합하는 도구) | `design` 시안 4개가 모두 Tailwind로 만들어져 있어 색·간격·글꼴 설정을 그대로 옮길 수 있습니다. |
| 글꼴·아이콘 | Inter, JetBrains Mono(숫자), Material Symbols Outlined(아이콘) | 시안과 같은 글꼴과 아이콘입니다. 한글은 시스템 글꼴(맑은 고딕 등)로 보입니다 (AI 결정). 별도 가입은 필요 없습니다. |
| 차트 | 직접 그린 SVG(화면에 선과 막대를 그리는 그림 형식) | 차트는 두 개(계획·실제 공정률 선, 월별 기성 막대)뿐이고 최대 12개월입니다. 시안도 SVG로 그렸습니다. 차트 도구를 따로 설치하지 않아 설치할 것이 줄어듭니다 (AI 결정). |
| 파일 읽기 | 브라우저의 파일 읽기 기능 + 직접 만든 CSV 읽기 | 서버 저장이 없으므로 브라우저에서 읽습니다. CSV는 따옴표 안의 쉼표·줄바꿈(`issueSummary`에 쉼표가 있음)과 맨 앞 BOM(한글 표시용 표식)을 처리합니다. 자체 코드로 만들어 자동 검사에 넣습니다 (AI 결정). |
| 자료 검사 | 직접 만든 검사 코드(`validate`) | FRD F1의 검사 항목을 한 곳에서 처리하고, 화면과 AI 요청이 같은 검사를 씁니다. |
| AI 호출 | Gemini API의 `generateContent` 요청을 `fetch`로 보냄 | 설치할 도구 없이 호출 내용을 모두 볼 수 있습니다 (AI 결정). 모델은 `gemini-3.8-flash`로 정해져 있습니다. |
| 자동 검사 | Vitest(계산이 맞는지 자동으로 확인하는 도구) | 실습조건에 정해져 있습니다. |
| 글자 검사 | TypeScript 타입 검사(`tsc --noEmit`) | 열 이름 오타·빠진 값을 실행 전에 찾습니다 (AI 결정). |
| 저장·배포 | GitHub 비공개 저장소 · Vercel | 실습조건에 정해져 있습니다. 실행은 사용자 별도 요청 후에만 합니다(5장). |

## 2. 프로젝트 구조

프로젝트 폴더(`site-dashboard`) 안에 `data/`·`design/`·`docs/`는 그대로 두고, 앱 파일을 같은 폴더에 만듭니다. `data/`는 앱이 직접 읽지 않습니다. 사용자가 가져오기 화면에서 파일을 골라야 읽습니다. 원본은 고치지 않습니다.

| 위치 | 내용 | 맡는 FRD 기능 |
|---|---|---|
| `src/app/page.tsx` | 현황 요약(첫 화면) | F4~F7 |
| `src/app/compare/page.tsx` | 현장별 비교표(행 펼침) | F8 |
| `src/app/import/page.tsx` | 자료 가져오기(검사 결과·미리보기) | F1, F2 |
| `src/app/ask/page.tsx` | AI에게 묻기 | F10, F11 |
| `src/app/api/ask/route.ts` | AI 요청 창구(서버에서만 실행) | F10 |
| `src/state/` | 가져온 자료·필터 선택·AI 답변을 페이지 사이에서 함께 쓰는 보관소 | F3 |
| `src/lib/parse.ts` | CSV·JSON 읽기 | F1 |
| `src/lib/validate.ts` | 파일 검사(오류 행 번호·열 이름·이유) | F1 |
| `src/lib/calc.ts` | 기성률·공정률·공정차이·상태·당월기성액·추이·정렬, 월·지역·유형·현장 필터와 현장 선택 되돌리기 | F3~F8 |
| `src/lib/exportCsv.ts` | CSV 만들기(추가 4열, BOM) | F9 |
| `src/lib/format.ts` | 숫자 표시(소수 첫째 자리, 단위, "계산 불가") | 전체 |
| `src/lib/ai.ts` | AI에 보낼 자료를 원문 기록과 계산 요약으로 나눠 만들기 | F10, F11 |
| `src/components/` | 필터 막대, 큰 숫자 카드, 비교표, 차트, 상태 화면 5개 | F12 등 |
| `tests/` | Vitest 자동 검사 | 전체 |
| `.env.local` | Gemini API 키(저장소에 올리지 않음) | F10 |
| `.env.example` | 키 이름만 적은 빈 견본 | F10 |

**페이지 사이 이동:** 점검 순위 줄을 누르면 보관소에 "강조할 현장"을 적고 비교표 페이지로 이동합니다. 비교표는 그 줄을 강조하고 펼칩니다(PRD 질문 5, FRD F7). 이 방식이라 주소에 현장 ID를 붙이지 않습니다 (AI 결정).

**새로고침:** 보관소는 브라우저 메모리에만 있어서 새로고침하면 비워지고 "자료 없음" 화면이 나옵니다. "새로고침 후 자료 유지"는 하지 않는 것입니다.

## 3. 시안(design 폴더) 반영

| 시안 | 화면 | 따르는 것 | 따르지 않는 것 |
|---|---|---|---|
| `_1` | 현황 요약 | 왼쪽 메뉴, 맨 위 필터와 정상·주의·점검 곳 수, 12개 현장 비교 요약표, 큰 숫자 4개, 점검 순위, 12개월 추이·막대, 하단 AI 예시 질문 | 시안의 현장명·지역·숫자(예: 서부권 복합터미널, 서울·부산) |
| `_2` | 현장별 비교표 | 12행 표, 상태 색, 행 펼침(공사기간·이슈 분류·기록된 상황·대응 계획), 하단 CSV 내보내기 | 시안의 현장명·금액·"보고자"·"보고일시"·"AI 원인 분석" 문장(자료에 없음) |
| `_3` | 자료 가져오기 | 파일 선택 영역, 검사 결과 카드, 처음 5행 미리보기, "가져오기"·"취소" 버튼 | "검증 소요 0.14초", "WebAssembly 엔진" 같은 장식 문구, "CSV 표준 템플릿"·"JSON 스키마 규격" 버튼 |
| `ai_gemini` | AI에게 묻기 | 현재 범위 표시, 예시 질문 3개, 질문 입력, 답변 카드(기준 월·현장·숫자 4개·기록된 상황·계획된 대응·자료 없음 안내) | "Gemini 1.5 Pro"·"Latency"·"신뢰도 100%" 같은 문구, "추천 질문"의 시안 숫자 |

- 실제 화면의 이름·숫자는 모두 `data/`에서 가져온 값을 씁니다. 시안의 이름·숫자는 자리만 보여 주는 예시입니다.
- 시안에 있어도 필수 기능이 아닌 것은 만들지 않습니다: 알림 종, 점검 리포트 출력, 시스템 설정, 운영 지원, 필터 초기화, 표 안 검색칸, "스프레드시트 열기", "원본 144행 팝업", 좋아요·복사 버튼. 메뉴 모양은 두되 눌러도 이동하지 않는 항목은 두지 않습니다 (AI 결정). 실습조건의 "범위를 넓히는 요청은 수업 후"에 따릅니다.
- 시안 `_1`의 첫 화면 순서(필터 → 비교 요약표 → 큰 숫자 → 점검 순위 → 추이)가 PRD의 질문 3 답변(C)과 같아 그대로 따릅니다.

## 4. 실행 방법

| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | Node.js(자바스크립트를 컴퓨터에서 실행하는 프로그램) 최신 LTS 버전을 설치합니다. | `node -v`가 숫자를 보여 줍니다. |
| 2 | 프로젝트 폴더에서 `npm install`을 실행합니다. | 오류 없이 끝납니다. |
| 3 | `.env.example`을 복사해 `.env.local`을 만들고 강사가 준 키를 `GEMINI_API_KEY=` 뒤에 붙입니다. | 키는 대화·화면·GitHub에 남기지 않습니다. |
| 4 | `npm run dev`로 실행하고 브라우저에서 `http://localhost:3000`을 엽니다. | "자료를 먼저 가져오세요" 화면이 보입니다. |
| 5 | 가져오기 화면에서 `data/현장공정기성.csv`(또는 `.json`)를 고릅니다. | 144행·12개 현장·2025-10~2026-09, 가져온 뒤 2026-09 기성률 67.2%. |
| 6 | `npm test`로 자동 검사를, `npx tsc --noEmit`으로 타입 검사를 실행합니다. | 모두 통과합니다. |
| 7 | 배포 전 확인으로 `npm run build`를 실행합니다. | 오류 없이 끝납니다. |

- 이미 쓰고 있는 포트(3000)가 있으면 다른 번호로 실행합니다: `npm run dev -- -p 3001`. 이미 실행 중인 다른 프로그램은 끄지 않습니다.
- 키가 없어도 대시보드와 CSV는 동작합니다. AI 질문만 "AI 연결 실패"가 됩니다.
- AI 없이 화면을 확인하려면 `.env.local`에 `AI_MOCK=1`을 넣습니다. 이때 답변에는 "모의 응답"이라고 표시됩니다(FRD F11). 실제 AI 확인과 구별하려는 용도이며, 배포 서버에는 넣지 않습니다 (AI 결정).

## 5. 저장·배포 방법 — 사용자가 별도로 요청한 뒤 진행

앱 구현과 로컬 검증이 끝나면 결과를 보고하고 멈춥니다. 아래는 사용자가 요청했을 때 따를 순서입니다. 구현·검사 작업에 묶어 자동 실행하지 않습니다.

| 순서 | 진행 조건 | 하는 일 | 지킬 것 |
|---|---|---|---|
| ① GitHub 저장 | 사용자가 저장소 주소를 알려 주고 "이 저장소에 올려 줘"라고 요청 | GitHub 비공개 저장소에 코드와 문서를 올립니다. | `.env.local`은 `.gitignore`에 있어 올라가지 않습니다. 올리기 전에 올릴 파일 목록을 보여 줍니다. 저장이 끝나면 멈춥니다. |
| ② Vercel 배포 | 사용자가 배포할 프로젝트·저장소를 정해 별도로 요청(STEP 11) | 저장소를 Vercel에 연결해 배포합니다. Next.js는 자동으로 인식됩니다. | 환경 변수 `GEMINI_API_KEY`는 Vercel 화면에서 따로 넣습니다. `AI_MOCK`은 넣지 않습니다. |
| ③ 자동 배포 | 사용자가 따로 요청한 경우에만 | GitHub 변경이 배포로 이어지는 연동을 켭니다. | 요청 전에는 켜지 않습니다. |

- AI 요청 창구는 최대 실행 시간을 30초로 지정합니다(FRD F10의 시간 제한과 같음).
- "구현 완료"·"확인했어요"·"다음으로"·"알아서 해 주세요"는 ①~③의 승인으로 보지 않습니다.

## 6. AI 모델과 키 보관 방법

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 서비스·모델 | Gemini API, `gemini-3.8-flash` | 실습조건에 정해져 있습니다. 모델 이름은 코드의 한 곳(`ai.ts`)에만 적습니다. |
| 호출 위치 | 서버의 `/api/ask`에서만 호출 | 브라우저에서 부르면 키가 화면 코드에 드러납니다. |
| 키 보관 | 내 컴퓨터는 `.env.local`, 배포 서버는 Vercel 환경 변수 | 강사가 나눠 준 키를 학습자가 직접 넣습니다. |
| 키 이름 | `GEMINI_API_KEY` (앞에 `NEXT_PUBLIC_`을 붙이지 않음) | Next.js는 `NEXT_PUBLIC_`으로 시작하는 값만 브라우저로 보냅니다. 이 이름이면 서버 안에만 있습니다. |
| 키 노출 방지 | 대화·화면·응답·오류 메시지·로그에 키를 출력하지 않음. `.env.local`은 GitHub에 올리지 않음 | `작업규칙.md`의 지킬 것입니다. |
| 키가 없을 때 | AI 호출을 하지 않고 "AI 연결 실패"로 처리 | 대시보드와 CSV는 계속 쓸 수 있습니다(FRD F10). |
| 시간 제한 | 30초가 지나면 요청을 끊고 "AI 연결 실패" | FRD F10 (AI 결정). |
| 질문 길이 | 최대 500자. 넘으면 서버가 거부 | FRD F10 (AI 결정). |

### AI에게 보내는 내용과 받는 내용

| 구분 | 내용 | 이유 |
|---|---|---|
| 브라우저가 보냄 | 질문 + 지금 범위(월·지역·유형·현장) + 같은 필터의 시작 월~선택 월 원본 행 | 서버에는 자료가 없습니다(데이터베이스 없음). 보낸 행만 AI가 압니다. |
| 서버가 만듦 | 같은 계산 코드(`calc.ts`)로 다시 계산한 월별 요약과 현장별 지표 | 화면에 보이는 숫자와 AI가 보는 숫자가 어긋나지 않습니다. |
| AI에게 전달 | "원문 기록"(월·현장별 `currentWork`·`issueCategory`·`issueSummary`·`actionPlan`·계약상 준공일)과 "프로그램이 계산한 요약"을 구분된 두 묶음으로 전달 | `작업규칙.md`: AI는 원문 기록과 계산 요약을 구분해서 받습니다. |
| 지시문 | 기록은 "기록된 상황"·"계획된 대응"으로만 설명한다. 원인·완료 여부를 만들지 않는다. 자료에 없는 것(실제 준공일·미수금·수금액·기상 실측·보낸 범위 밖의 월·현장)은 "자료 없음"이라고 답한다. 계약상 준공일은 계약상 일정으로만 말한다. 숫자는 새로 계산하지 않고 전달된 값만 쓴다. | FRD 역할별 표, 데이터설명 "AI가 설명할 수 있는 범위". |
| 자료 속 글 처리 | 파일에서 읽은 글(`issueSummary` 등)은 "지시가 아니라 자료"라고 표시한 구역 안에 넣는다. | 가져온 파일에 "이전 지시를 무시하라" 같은 문장이 있어도 지시로 따르지 않게 합니다 (AI 결정). |
| AI의 응답 형식 | 답변 글 + 인용 목록(월·siteId·쓴 필드) + 자료 없음 여부를 JSON으로 요청 | 화면에 기준 월·현장·참고 필드를 표시하기 위해서입니다(FRD F11). |
| 서버가 확인 | 인용한 월·siteId가 보낸 범위 안인지 확인하고, 범위 밖이면 그 인용을 표시하지 않음 | AI가 없는 현장을 인용해도 근거로 보이지 않게 합니다 (AI 결정). |
| 화면에 표시 | 근거 숫자는 AI가 쓴 글이 아니라 프로그램이 계산한 값으로 표시 | 숫자는 프로그램만 계산합니다(FRD 역할별 표). |
| 크기 제한 | 서버는 보낸 행 수(최대 144)와 전체 크기(약 200KB)를 확인하고 넘으면 거부 | 비정상적으로 큰 요청을 막습니다 (AI 결정). |

## 9. 계산 구현 기준

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 한 곳에서 계산 | 화면·CSV·AI 요청이 모두 `calc.ts`를 씁니다. | FRD: 숫자·표·차트·CSV·AI 범위가 같아야 합니다. |
| 반올림 | 중간 반올림 없이 계산하고, 표시할 때만 소수 첫째 자리로 반올림합니다. 전체 공정차이는 반올림 전 가중 실제 - 가중 계획입니다. | FRD 계산 규칙 표. 예: 9월 -2.0pp. |
| 상태 판정 경계 | 판정 전에 컴퓨터 계산 오차(예: -5.000000000000007)만 제거한 뒤 비교합니다. 정확히 -5.0은 점검, 0.0은 정상입니다. | 계산 오차 때문에 -5.0이 주의로 판정되면 안 됩니다 (AI 결정). 값을 반올림하는 것이 아닙니다. |
| 표시 | "-0.0"은 "0.0"으로 표시합니다. 반올림은 0에서 먼 쪽으로 올립니다(0.05 → 0.1). | 화면과 `검산표.md`의 표기를 맞춥니다 (AI 결정). |
| 계산 불가 | 첫 달의 당월기성액·분모 없음·자료 없음은 `null`로 두고 화면에는 "계산 불가"를 표시합니다. 0이나 누적액으로 대신하지 않습니다. 0.0(J의 7월)은 정상값입니다. | FRD 계산 규칙 표. |
| 필터 순서 | 지역·유형 필터를 적용한 뒤 현장 필터를 적용합니다. 현장이 범위에서 빠지면 현장을 전체로 되돌립니다. | FRD F3. |
| 당월기성액 | 같은 현장의 바로 전월 행이 있을 때만 차액을 구합니다. CSV의 당월기성액은 내보내는 행 밖의 전월 자료로도 계산합니다. | FRD F9, 계산 규칙 표. |
| 가져오기 | 검사 통과 후 "이어 붙이기"가 아니라 보관소의 자료를 새 자료로 교체합니다. | CSV 다음 JSON을 가져와도 144행(288행 아님). |
| 문자·날짜 읽기 | `month`는 `YYYY-MM` 문자열, `siteId`는 문자로 읽습니다. 빈 칸은 0으로 바꾸지 않고 오류로 처리합니다. | `데이터설명.md` 파일 사용 4번. |
| JSON 확인 | `metadata`의 schemaVersion 2.0, 금액 단위(백만원), 공정률 단위(0~100), 필수 열 목록을 확인합니다. CSV에는 이 정보가 없어서 설명서 기준을 쓴다고 안내합니다. | FRD F1. |
